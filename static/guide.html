دليل عملي — الإصدار 3.0

إزاي تعدّل على GitHub وإزاي تشغّل البروكسي

كل حاجة خطوة بخطوة: تعديل الملفات من المتصفح، رفع التحديثات، إضافة متجر جديد، وتشغيل البروكسي عشان السكرابينج الحي يشتغل.

محتويات الدليل 1) تعديل ملف موجود على GitHub من المتصفح 2) رفع ملفات جديدة (صور/ملفات) على GitHub 3) التعديل من الكمبيوتر بأوامر git 4) إضافة متجر جديد في 3 خطوات 5) البروكسي: ليه محتاجينه؟ 6) تشغيل البروكسي على Render 7) تشغيل البروكسي محليًا (.env) 8) اختبار البروكسي وقراءة النتيجة 9) أخطاء شائعة وحلولها 10) الموبايل واللغة وأدوات الذكاء الاصطناعي

1 تعديل ملف موجود على GitHub من المتصفح

أسهل طريقة — من غير أي برامج. كل اللي محتاجه حساب GitHub ومستودع المشروع مرفوع عليه.

  1. افتح صفحة المستودع: https://github.com/<اسمك>/price-hunter.
  2. افتح الملف اللي عايز تعدّله (مثلًا static/index.html أو scrapers/stores.py).
  3. اضغط أيقونة القلم ✏️ (Edit this file) فوق على يمين الملف.
  4. عدّل اللي انت عايزه. لو الملف كبير استخدم Ctrl+F للوصول للسطر.
  5. انزل تحت خالص → في خانة Commit changes اكتب وصف قصير (مثل: إضافة متجر جديد).
  6. اختار Commit directly to the main branch واضغط Commit changes.
بعد الـ Commit Render بيراقب الفرع main وبيعمل نشر تلقائي (Auto-Deploy) خلال دقيقة أو دقيقتين. تقدر تتابع التقدّم من تاب Logs في Render.
مهم أي تعديل في app.py أو scrapers/ أو static/ محتاج إعادة نشر (بتحصل لوحدها). لو الموقع مش بيتحدّث: من Render اضغط Manual Deploy → Deploy latest commit.

2 رفع ملفات جديدة على GitHub (صور المنتجات مثلًا)

  1. من صفحة المستودع اضغط Add file → Upload files.
  2. اسحب الصور أو الملفات وارميها في الصفحة (أو choose your files).
  3. لو الملفات جوه فولدر: اكتب مسار الفولدر في خانة الاسم، مثال: static/img/products/.
  4. اكتب وصف في Commit changes → اضغط Commit changes.
مقاسات مقترحة لصور المنتجات صورة مربعة 200×200 بكسل بصيغة .jpg أو .webp وحجم أقل من 40 كيلوبايت — كده الصفحة تفضل سريعة على الموبايل. صور الديمو الحالية في static/img/products/.

3 التعديل من الكمبيوتر بأوامر git

لو التعديلات كتير، أنزّل المشروع وعدّل عليه محليًا وبعدين ارفع.

# 1) نزّل المشروع أول مرة
git clone https://github.com/<اسمك>/price-hunter.git
cd price-hunter

# 2) عدّل الملفات على جهازك (VS Code أو أي محرر)

# 3) شوف اللي اتغيّر
git status
git diff

# 4) سجّل التعديل وارفعه
git add -A
git commit -m "إضافة متاجر جديدة + صور المنتجات + دعم اللغتين"
git push origin main
نصيحة قبل أي push اعمل git pull --rebase لو فيه تعديلات من المتصفح، عشان تتجنّب تعارض الملفات (Merge conflict).

4 إضافة متجر جديد في 3 خطوات

المتاجر كلها مسجّلة في ملف واحد: scrapers/stores.py. إضافة متجر = سطر واحد.

  1. افتح scrapers/stores.py على GitHub واضغط ✏️.
  2. ضيف السطر ده جوه قائمة EXTRA_STORES (غيّر القيم حسب المتجر): 
    StoreProfile("mystore", "اسم المتجر بالعربي", "Store Name", "#4f8cff",
             "magento",        # shopify | woocommerce | magento | generic
             "https://mystore.com/catalogsearch/result/?q={q}",
             "https://mystore.com", "mystore.com"),
  3. اعمل Commit → Render هيعمل نشر لوحده → ابحث وشوف المتجر ظهر في الشرائح.

إزاي تختار نوع المحرك (engine)؟

المحركيستخدم إمتى
shopifyالموقع عليه /search?q= وShopify في الكود المصدري
woocommerceووردبريس/وودمارت — لينكات فيها /product/
magentoروابط /catalogsearch/result/?q=
genericمش متأكد؟ ده بيلقط JSON-LD و__NEXT_DATA__ وأي كروت منتجات
لو المتجر ظهر «محجوب» يبقى الموقع بيرفض طلبات السيرفرات (Cloudflare / حماية بوتات) — الحل هو البروكسي في الجزء الجاي، وممكن كمان تحدد بروكسي خاص للمتجر ده: MYSTORE_PROXY.

5 البروكسي: ليه محتاجينه أصلًا؟

جوميا ونون وأمازون و2B وبي تك ورنين… كلهم وراهم حماية (Cloudflare وغيرها) بترفض الطلبات الجاية من IP سيرفرات زي Render. لما الموقع بتاعنا يطلب صفحة البحث منهم بيرجّع 403 / 429 أو صفحة تحقق، فالنتيجة تظهر «محجوب».

الحل: نعدّي الطلبات من IP سكني (Residential) أو موبايل مصري — كأن الزائر إنسان عادي. الكود جاهز للده 100%: بمجرد ما تحط قيمة البروكسي، كل السكرابرز بقت بتعدي منه تلقائيًا.

نوع البروكسيالنتيجة مع المتاجر المصرية
داتا سنتر (Datacenter)بيتحظر غالبًا
سكني (Residential)أفضل نتيجة
موبايل (4G/5G)ممتاز
سيرفر داخل مصر (VPS)بيشتغل مع بعض المتاجر

6 تشغيل البروكسي على Render (خطوة بخطوة)

  1. افتح dashboard.render.com → اختار الخدمة price-hunter-egypt.
  2. من القائمة الجانبية: Environment.
  3. اضغط Add Environment Variable.
  4. Key = PROXY_URL — Value = رابط البروكسي بالشكل: 
    http://USERNAME:PASSWORD@HOST:PORT
  5. اضغط Save Changes → Render هيعمل Redeploy تلقائي (استنى 1–2 دقيقة).
  6. افتح https://اسم-موقعك.onrender.com/api/proxy-info للتأكد (الجزء 8).

المتغيرات المدعومة (كلها اختيارية)

المتغيرالوظيفة
PROXY_URLبروكسي واحد لكل المتاجر (الأسهل)
PROXY_LISTأكتر من بروكسي مفصولين بفاصلة — تدوير تلقائي
JUMIA_PROXY / NOON_PROXY / AMAZON_PROXY / BTECH_PROXY / VONTX_PROXY …بروكسي مخصص لمتجر معين (أو off لتعطيله)
PROXY_HOST + PROXY_PORT + PROXY_USERNAME + PROXY_PASSWORDبديل لو البيانات مش في رابط واحد
PROXY_ROTATEround (افتراضي) / random / sticky
PROXY_FALLBACK_DIRECT1 = يجرّب اتصال مباشر لو البروكسي فشل
SCRAPER_TIMEOUTمهلة الطلب بالثواني (افتراضي 8)
SCRAPER_RETRIESعدد المحاولات على بروكسيات مختلفة (افتراضي 2)
تحذير أمني متكتبش بيانات البروكسي في الكود ولا في GitHub أبدًا. خليها Environment Variables بس، وملف .env مستثنى في .gitignore.

7 تشغيل البروكسي محليًا

# 1) نزّل المكتبات
pip install -r requirements.txt

# 2) انسخ قالب الإعدادات
cp .env.example .env

# 3) افتح .env واملأ السطر ده
PROXY_URL=http://user:pass@host:port

# 4) شغّل الموقع
python app.py
# افتح http://localhost:8000

الصيغ المقبولة للبروكسي:

http://user:pass@host:port
https://user:pass@host:port
socks5://user:pass@host:port
host:port
host:port:user:pass      # صيغة شائعة عند بعض المزودين

8 اختبار البروكسي وقراءة النتيجة

افتح في المتصفح: https://اسم-موقعك.onrender.com/api/proxy-info

هتلاقي حقل verdict — معناه كده:

النتيجةالمعنىالتصرف
proxy_ok شغالالبروكسي بيرد و IP الخروج مختلف عن IP السيرفرمفيش حاجة — السكرابينج الحي شغال
no_proxy مفيش بروكسيمفيش أي متغير متظبطضيف PROXY_URL
proxy_failed فاشلالبروكسي متظبط بس مش واصلراجع العنوان/المنفذ/اليوزر/الباسورد والاشتراك
تنبيه ذكي لو exit_ip بتاع البروكسي نفس exit_ip بتاع الاتصال المباشر، يبقى البروكسي مش شغال فعلًا (بيعدّي من غير تحويل).

كمان تقدر تجرّب البحث مباشرة: https://اسم-موقعك.onrender.com/api/search?q=iphone — وشوف حقل stores[].status: ok يعني نجح، blocked يعني محتاج بروكسي.

9 أخطاء شائعة وحلولها

الخطأالسببالحل
407بيانات الدخول غلط أو ناقصةراجع اليوزر/الباسورد، ولو فيه رموز خاصة اعمل URL-encode أو استخدم PROXY_HOST + PROXY_PORT
403 / 429 من المتجرالبروكسي داتا سنتر أو محظوراستخدم بروكسي سكني/موبايل، أو PROXY_LIST للتدوير
ConnectTimeoutالبروكسي بطيء أو مقطوعزوّد SCRAPER_TIMEOUT أو غيّر البروكسي
UnsupportedProtocolsocks5 من غير مكتبةموجودة أصلًا في requirements.txt (httpx[socks]) — تأكد إن النشر نزّل المكتبات
الموقع بطيء جدًامتجر مش بيردطبيعي: بعد أول فشل بنتخطى المتجر مؤقتًا (Circuit breaker) والبحث اللي بعده يبقى أسرع

10 الموبايل واللغة وأدوات الذكاء الاصطناعي

اللغة (عربي / إنجليزي)

زرار اللغة فوق على الشمال في الهيدر: عربي | EN. التغيير بيقلب اتجاه الصفحة (rtl ↔ ltr) وبيتحفظ في المتصفح (localStorage) فالمستخدم مش محتاج يختار كل مرة.

الموبايل

التصميم متجاوب بالكامل: الجدول بيتحوّل لكروت على الشاشات الصغيرة، الصور بمقاس صغير (64 بكسل) وloading="lazy"، والأزرار بتكبر للمس، والشرائح بتتزحلق أفقيًا. مفيش أي تمرير أفقي في الصفحة.
